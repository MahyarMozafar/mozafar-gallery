# گالری مظفر — Mozafar Gallery

فروشگاه آنلاین طلا و جواهر. فارسی، راست‌به‌چپ، با قیمت لحظه‌ای.

---

## راه‌اندازی

```bash
npm install
npm run seed     # پایگاه داده را می‌سازد و محصول‌های نمونه را می‌ریزد
npm run dev      # http://localhost:3000
```

پنل مدیریت: <http://localhost:3000/admin>

| دستور | کار |
|---|---|
| `npm run dev` | سرور توسعه |

## قیمت چطور حساب می‌شود؟

```
ارزش طلا   = وزن × نرخ گرم آن عیار
اجرت       = ارزش طلا × درصد اجرت
سود        = (ارزش طلا + اجرت) × درصد سود     ← روی طلا+اجرت، نه فقط اجرت
مالیات     = (اجرت + سود) × درصد مالیات        ← هرگز روی خود طلا
قیمت نهایی = جمع همه
```

دو نکته که خیلی‌ها اشتباه می‌کنند:

1. **سود روی «طلا + اجرت»** حساب می‌شود، نه فقط روی اجرت.
2. **مالیات هرگز روی خود طلا** بسته نمی‌شود. طلای خام طبق ماده ۲۶ قانون مالیات بر
   ارزش افزوده معاف است. بستن مالیات روی کل فاکتور تخلف است.
3. مالیات برای ۱۴۰۴/۱۴۰۵ برابر **۱۰٪** است (قبلاً ۹٪ بود). در تنظیمات قابل تغییر است.

### فقط یک عدد از API گرفته می‌شود

نرخ **گرم ۱۸ عیار** گرفته می‌شود و بقیه از رویش حساب می‌شوند:

| عیار | فرمول |
|---|---|
| ۲۱ عیار | `۱۸عیار × ۸۷۵ ÷ ۷۵۰` |
| ۲۴ عیار (آب‌شده) | `۱۸عیار × ۹۹۵ ÷ ۷۵۰` |
| نرخ خرید از مشتری | `۱۸عیار × ۷۴۰ ÷ ۷۵۰` |
| مثقال | `۱۸عیار × ۴٫۶۰۸ × ۷۰۵ ÷ ۷۵۰` |

این را از روی سایت‌های واقعی پیدا کردم: در `nabigold.com` عدد
`۱۹٬۹۵۰٬۰۰۰ × ۹۹۵ ÷ ۷۵۰ = ۲۶٬۴۶۷٬۰۰۰` دقیقاً با ۲۴ عیار نمایشی‌شان یکی بود.
فایده‌اش: درخواست کمتر، و عیارها هیچ‌وقت با هم نمی‌خوانند نمی‌شوند.

## سه مسئله سخت و راه‌حلشان

### ۱. دو نفر یک انگشتر را همزمان می‌خرند

بیشتر قطعه‌ها تک‌نسخه‌ای هستند (موجودی = ۱).

**روش غلط:** موجودی را بخوان → چک کن > ۰ → بنویس صفر.
اگر دو نفر همزمان این کار را بکنند، هر دو «۱» می‌بینند و یک انگشتر دو بار فروخته می‌شود.

**روش درست** (`src/lib/db/stock.ts`) — شرط و تغییر در یک دستور:

```sql
UPDATE products SET stock = stock - 1 WHERE id = ? AND stock >= 1
```

پایگاه داده تضمین می‌کند فقط یکی برنده شود. بقیه پیام «فروخته شد» می‌گیرند.

**تست شده:** ۵۰ درخواست همزمان برای ۱ قطعه → دقیقاً ۱ برنده، ۴۹ بازنده، موجودی ۰.

### ۲. قیمت وسط خرید عوض می‌شود

بدون تایمر و شمارش معکوس. قیمت **یک بار** موقع «ثبت سفارش» حساب و داخل سفارش
نوشته می‌شود و بعد از آن هرگز عوض نمی‌شود — حتی اگر نرخ طلا بالا و پایین برود.
فاکتور ماه‌ها بعد هم همان عدد را نشان می‌دهد.

### ۳. ۱۰٬۰۰۰ نفر همزمان

نرخ طلا **۶۰ ثانیه کش** می‌شود (`src/lib/shop.ts`). یعنی هر چقدر آدم بیاید،
فقط دقیقه‌ای یک بار سراغ منبع می‌رویم — **۱٬۴۴۰ درخواست در روز**، ثابت.

نتیجه تست فشار روی همین لپ‌تاپ:

| صفحه | درخواست/ثانیه | p95 | خطا |
|---|---|---|---|
| صفحه اصلی | ۸۳۳ | ۱۳ms | ۰ |
| صفحه محصول | ۳۴۷ | ۲۹۶ms | ۰ |
| فروشگاه (۲۱ محصول) | ۲۸۴ | ۳۴۸ms | ۰ |

## ورود

ورود با **شماره موبایل و کد پنج‌رقمی**. دکمه «ثبت‌نام» جدا نداریم — شماره‌ای که
تا حالا دیده نشده، خودش تبدیل به حساب می‌شود.

**در حالت ساخت پیامک واقعی فرستاده نمی‌شود.** کد هم در ترمینال چاپ می‌شود و هم
روی خود صفحه در یک کادر زرد نشان داده می‌شود، تا کار کردن راحت باشد.
برای واقعی کردن، فقط `src/lib/auth/sms.ts` را پر کنید و در `.env` بنویسید
`SMS_PROVIDER=kavenegar`. هیچ جای دیگری عوض نمی‌شود.

نکته‌های امنیتی که رعایت شده:

- کد **خام ذخیره نمی‌شود**، فقط هش SHA-256 آن
- **توکن نشست هم هش می‌شود** — اگر پایگاه داده لو برود، کسی نمی‌تواند وارد شود
- هر کد **۲ دقیقه** اعتبار دارد و فقط **یک بار** قابل استفاده است
- حداکثر **۵ تلاش** برای هر کد
- بین دو درخواست کد، **۶۰ ثانیه** فاصله لازم است
- کوکی نشست `httpOnly` است — جاوااسکریپت صفحه نمی‌تواند بخواندش
- `returnTo` فقط مسیر داخلی را قبول می‌کند (جلوی فرستادن کاربر به سایت بیرونی)

### کجا ورود لازم است؟

فقط **دو جا**: دکمه «ثبت سفارش» و صفحه حساب کاربری (و کل پنل مدیریت).

بقیه سایت کاملاً باز است: خانه، فروشگاه، فیلتر، صفحه محصول، ماشین‌حساب، مجله،
**و حتی اضافه کردن به سبد خرید**.

## سبد خرید

- مهمان هم سبد دارد. شناسه سبد در یک کوکی می‌ماند و **۳۰ روز** زنده است.
- موقع ورود، سبد مهمان **با حساب کاربر ادغام می‌شود** — چیزی گم نمی‌شود.
- تعداد اقلام روی دکمه سبد در بالای سایت نشان داده می‌شود.
- **افزودن به سبد، موجودی را رزرو نمی‌کند.** چون سبد برای مهمان‌ها باز است؛
  اگر قفل می‌کرد، یک نفر بدون ورود می‌توانست کل موجودی مغازه را ببندد.
  رزرو فقط موقع ثبت سفارش انجام می‌شود.
- اگر قطعه‌ای وقتی داخل سبد کسی است فروخته شود، «فروخته شد» نشان داده می‌شود
  و موقع ثبت سفارش کنار گذاشته می‌شود — بی‌سروصدا حذف نمی‌شود.

## پنل مدیریت

پشت ورود است و فقط کاربر با نقش `ADMIN` می‌تواند واردش شود.
هر مسیر API هم **جداگانه** دوباره چک می‌کند — نه فقط صفحه.

| بخش | چه کاری می‌کند |
|---|---|
| داشبورد | ارزش کل موجودی به تومان، وزن کل طلا، تعداد محصول، رسیدهای در انتظار |
| **نرخ طلا** | **وارد کردن دستی نرخ گرم ۱۸ عیار** — بقیه عیارها خودکار حساب می‌شوند |
| محصولات | جدول کامل با قیمت لحظه‌ای هر قطعه |
| محصول تازه | ساخت محصول با آپلود عکس و **پیش‌نمایش زنده قیمت** |
| ویرایش محصول | همان فرم، برای تغییر یا حذف |
| سفارش‌ها | لیست سفارش‌ها و وضعیت رسید |
| تنظیمات | درصدها، هزینه ارسال، شماره کارت، مدت رزرو و مهلت پرداخت |

### وارد کردن دستی نرخ طلا

روی داشبورد یک کادر زرد هست. فقط **یک عدد** می‌خواهد: نرخ گرم ۱۸ عیار.
۲۱ عیار، ۲۴ عیار و نرخ خرید (۷۴۰) همان‌جا زنده حساب و نشان داده می‌شوند.
با ذخیره، قیمت **همه‌ی محصولات با هم** عوض می‌شود.

وصل شدن به API واقعی برای بعد گذاشته شده. کدش آماده است
(`src/lib/pricing/derive.ts` و رابط `goldProvider` در تنظیمات) و فقط کلید می‌خواهد.

### ساخت محصول

قیمت را **دستی وارد نمی‌کنید**. وزن، عیار و اجرت را می‌دهید و قیمت از فرمول
حساب می‌شود. کنار فرم، نتیجه را زنده می‌بینید — قبل از اینکه ذخیره کنید.

عکس را می‌توانید **بکشید و رها کنید** یا کلیک کنید. فقط JPG، PNG، WebP و AVIF،
تا ۶ مگابایت. نام فایل را خودمان می‌سازیم — نام فرستاده‌شده هرگز قابل اعتماد نیست.
عکس‌های آپلودشده در `public/uploads/` می‌مانند و **به گیت نمی‌روند**.

## چیزهایی که هرگز به گیت نمی‌روند

فایل `.gitignore` از اولین کامیت این‌ها را می‌بندد:

- `.env` — کلید API طلا، رمز پایگاه داده، کلید پیامک
- `/private-uploads` و `/receipts` — **عکس رسید بانکی مشتری‌ها**؛ شماره کارت دارند
- `/public/uploads/*` — عکس‌های آپلودشده (خود پوشه می‌ماند، فایل‌ها نه)
- `data/*.db` — پایگاه داده (شماره موبایل مشتری‌ها و نشست‌ها داخلش است)
- `node_modules` و `.next`

شماره کارت مغازه هم در **تنظیمات پایگاه داده** است، نه داخل کد.
